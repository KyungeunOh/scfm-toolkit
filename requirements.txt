# 제거한 것들:
#   - torch / torchvision / torchaudio / triton  -> Dockerfile에서 베이스 이미지가 이미 제공
#   - flash-attn                                  -> Dockerfile에서 별도 빌드 단계로 처리 (소스 컴파일 필요)
#   - conda 자체 패키지 -> 컨테이너 운영에 불필요
#   - "@ file:///..." 형태의 로컬 conda 빌드 경로가 붙은 패키지 -> 버전만 남김
#   - session-info2, scverse-misc, treescope
#       -> HPC 미러에 패키지 자체가 없음(versions: none).
#          셋 다 핵심 기능 무관 확인됨:
#          session-info2: scanpy의 옵셔널 디버그용 환경정보 출력 도구
#                         (없어도 import 에러 안 나고 폴백됨)
#          scverse-misc: scverse 생태계 잡유틸 모음, scGPT/scanpy 핵심 무관
#          treescope: JAX/Flax 텐서 시각화용 pretty-printer, 학습/추론 로직 무관
#          -> 셋 다 requirements.txt에서 제거. 빌드 검증 단계에서
#             import scgpt, import scanpy가 실제로 깨지지 않는지 확인 필요.
#
# 2026-09-03: Geneformer 전용 의존성(transformers/peft/bitsandbytes/optuna/
# ray/loompy)을 requirements-geneformer.txt로 분리했다 (아래 "GRN 전용" 절
# 다음에 있던 절 참고 - git 히스토리에서 확인 가능). 이유: 이 파일 전체를
# `docker build`가 `pip install -r requirements.txt`로 한 번에 설치하는데,
# Geneformer 절의 `transformers==4.46.*`(huggingface-hub<1.0 요구)가 위쪽
# scGPT 스택의 `huggingface_hub==1.8.0`과 직접 충돌해서 mode: grn용
# networkx/gseapy를 추가해 이미지를 재빌드하려던 시점에 처음으로 pip
# ResolutionImpossible 에러가 실제로 터짐(이전 빌드들은 이 줄이 안 바뀌어서
# Docker 레이어 캐시가 이 pip install 단계를 건너뛰어 왔던 것으로 추정 -
# 즉 이 충돌은 새로 생긴 게 아니라 원래 있었는데 한 번도 실제로 검증된 적이
# 없었던 것). Geneformer 자체가 PyPI 패키지가 아니라 별도 `pip install .`가
# 필요한 것과 마찬가지로, 이 부가 의존성들도 scGPT 이미지 빌드와 분리하는 게
# 맞다고 판단함 - Dockerfile은 이 파일(requirements.txt)만 설치한다.
# =========================================================================

# --- GRN(mode: grn) 전용 - 2026-09 추가 ---
# scGPT Tutorial_GRN.ipynb 방식(유전자 임베딩 클러스터링 + pathway enrichment)을
# 재구현하는 데 필요한 새 의존성. 둘 다 이전까지는 이 프로젝트에 없던 패키지라
# 이 requirements.txt를 반영하려면 Docker 이미지 재빌드가 필요함(README 참고).
#
# networkx: 유전자 유사도 네트워크 그래프 구성용. GitHub의 pyproject.toml을 태그별로
#   직접 확인한 결과 networkx의 main(개발) 브랜치는 이미 requires-python>=3.12로
#   올라가 있어 이 프로젝트의 Python 3.10.11 이미지에 안 맞는다(scib 때와 동일한
#   함정) - 3.10을 지원하는 마지막 계열인 3.4.2로 고정.
# gseapy: Reactome pathway enrichment(gp.enrichr()) 호출용. 최신(1.3.1)도 확인했으나
#   HPC pip 미러가 "오래된 시점에 멈춰있는 미러"라는 이 파일 맨 위 경고를 고려해,
#   더 오래됐고(따라서 미러에 있을 가능성이 더 높고) manylinux cp310 prebuilt wheel이
#   확인된 1.0.4로 보수적으로 고정함 (gseapy는 Rust 확장을 빌드에 쓰지만 이 버전은
#   prebuilt wheel이 있어 소스 빌드/Rust 툴체인이 필요 없음 - Geneformer 때 겪은
#   "C 확장 소스 빌드 필요" 함정을 피하기 위해 의도적으로 최신 버전을 피함).
#   enrichr()는 Enrichr(maayanlab.cloud) 온라인 API를 호출한다 - gnode01의 실제
#   인터넷 접근 여부는 아직 확인된 적이 없음(README "알려진 제약" 참고, 실패해도
#   나머지 mode: grn 결과는 정상 저장되도록 코드에서 처리함).

gseapy==1.0.4
